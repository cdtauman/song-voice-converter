# תוכנית הפיתוח — שלב אחר שלב

**איך זה עובד:** כל שלב עצמאי, מסתיים במשהו שאפשר להריץ ולבדוק, ומתמזג ל-`main` עם תגית גרסה.
כשתגיד "Start Phase N" — אני אבנה בדיוק את מה שכתוב שם ולא אשנה את הארכיטקטורה תוך כדי.

**מה זה MVP:** שלבים 1–8. בסופם יש תוכנה שעובדת מקצה לקצה עם ממשק גרפי,
עם קולות שכבר קיימים. שלבים 9–12 הופכים אותה למוצר שלם עם אימון והתקנה.

---

## Phase 0 — מחקר ותכנון ✅ הושלם

**מטרה:** להבין את הבעיה, לבחור טכנולוגיות, לבנות תוכנית.
**תוצרים:** [research.md](research.md), [architecture.md](architecture.md), roadmap.md, [testing.md](testing.md), [decisions.md](decisions.md), [models.md](models.md).
**Definition of Done:** המסמכים בריפו + ההחלטות הפתוחות הוכרעו.

## Phase 1 — שלד ותשתית

**מטרה:** להקים פרויקט Python תקין שיודע לזהות את החומרה ולדווח שהכול מוכן.

**מה בונים:**
- `pyproject.toml` עם ניהול תלויות (uv), Python 3.11
- מבנה התיקיות המלא לפי [architecture.md](architecture.md#3-מבנה-התיקיות-בריפו)
- מודול `diag` — "רופא המערכת": בודק GPU, גרסת CUDA, VRAM פנוי, ffmpeg, מקום בדיסק
- מערכת לוגים (קובץ מסתובב + פלט קונסולה)
- מערכת קונפיגורציה (ברירות מחדל + הגדרות משתמש)
- שלד ה-RPC בין המנוע לממשק + בדיקת ping/pong
- CI ראשוני: ruff + mypy + pytest

**קבצים עיקריים:** `src/svc_engine/diag/`, `src/svc_engine/rpc/`, `src/svc_engine/config.py`, `.github/workflows/ci.yml`

**איך בודקים:** מריצים `svc doctor` ומקבלים דוח בעברית:
```
✅ כרטיס מסך: NVIDIA RTX 2000 Ada  (16GB, 15.2GB פנויים)
✅ CUDA 12.8
✅ ffmpeg
✅ מקום בדיסק: 240GB פנויים
```

**Definition of Done:** `svc doctor` עובד; CI ירוק; `pytest` עובר.
**מה עוד לא עושים:** שום עיבוד שמע. שום ממשק גרפי.

## Phase 2 — מנוע ההפרדה

**מטרה:** להפריד שיר לשכבות באיכות הכי טובה שיש, מקומית.

**מה בונים:**
- `audio/` — קליטה דרך ffmpeg, המרה ל-44.1kHz float32, ייצוא WAV/MP3
- `resources/` — ModelRegistry + DownloadManager (resume, checksum, retry, מראות)
- `separation/backends/` — מימוש `audio-separator` + מימוש `pymss` מאחורי ממשק אחיד
- `separation/ensemble.py` — שילוב תוצאות ממספר מודלים
- `separation/cleanup.py` — DeReverb / DeEcho / Denoise / הפרדת ווקאלים מלווים
- **שמירת שכבת ההדהוד בנפרד** (קריטי לשלב 6)
- שלוש רמות איכות: מהיר / מאוזן / איכות מרבית
- מנהל VRAM + סולם הנסיגה ל-OOM

**קבצים עיקריים:** `src/svc_engine/audio/`, `src/svc_engine/separation/`, `src/svc_engine/resources/`

**איך בודקים:**
```bash
svc separate "song.mp3" --quality balanced --out ./out
```
מקבלים `vocals.wav`, `instrumental.wav`, ובמידת הצורך `lead.wav`, `backing.wav`, `ambience.wav`.
בדיקה אובייקטיבית מול קבצי ייחוס (ראה [testing.md](testing.md)) + האזנה ידנית.

**Definition of Done:** הפרדה עובדת בשלוש רמות איכות; מודלים יורדים אוטומטית עם אימות checksum;
OOM מטופל אוטומטית; זמני העיבוד מתועדים.
**מה עוד לא עושים:** ניתוח, המרה, ממשק.

## Phase 3 — מנוע הניתוח

**מטרה:** להבין את השיר — גובה, מנעד, סולם, איפה כדאי לעשות Preview.

**מה בונים:**
- `analysis/f0.py` — RMVPE (עיקרי) + FCPE (מהיר), עם ממשק אחיד
- `analysis/range.py` — סטטיסטיקת מנעד משוקללת באנרגיה (p05…p95, min, max ב-MIDI)
- `analysis/key.py` — זיהוי סולם השיר (chroma + Krumhansl-Schmuckler)
- `analysis/segments.py` — זיהוי מקטעים עם/בלי שירה
- `analysis/preview_picker.py` — בחירת הקטע המייצג לפי הניקוד שתואר במחקר
- `profiles/` — חישוב פרופיל מנעד לקול יעד מתוך דגימת אודיו

**קבצים עיקריים:** `src/svc_engine/analysis/`, `src/svc_engine/profiles/`

**איך בודקים:**
```bash
svc analyze "vocals.wav" --report report.json --plot report.png
```
הגרף מראה את עקומת ה-F0 ואת גבולות המנעד. משווים ידנית מול השיר — האם החציון הגיוני?

**Definition of Done:** דוח ניתוח מלא לכל שיר בסט הבדיקה; פרופיל מנעד מחושב נכון לקול יעד;
בחירת קטע ה-Preview נותנת קטע הגיוני ב-5 מתוך 5 שירי הבדיקה.
**מה עוד לא עושים:** החלטות על הזזה, המרה.

## Phase 4 — מנוע המנעד וההזזה ⭐

**מטרה:** לפתור את הבעיה המרכזית — התאמת גובה השיר לקול היעד בצורה טבעית ואוטומטית.

**מה בונים:**
- `pitch/strategy.py` — פונקציית העלות והפירוק `s = 12k + r` (המפרט המלא ב-[research.md](research.md#4--הלב-של-הפרויקט-הפתרון-לפער-המנעד))
- `pitch/explain.py` — הפיכת ההחלטה למשפט בעברית פשוטה
- `pitch/shifter.py` — הזזת גובה איכותית עם שימור אורך, מאחורי ממשק ניתן להחלפה
- `pitch/instrumental.py` — פיצול הפלייבק ל-3 שכבות והזזה **בלי לגעת בתופים**
- `pitch/softening.py` — ריכוך קפיצות גובה (כבוי כברירת מחדל)

**קבצים עיקריים:** `src/svc_engine/pitch/`

**איך בודקים:**
- בדיקות יחידה על המתמטיקה: לפרופילים מוגדרים מראש, האם ההמלצה היא הצפויה?
  (למשל: שיר נשי טיפוסי + פרופיל בריטון → צריך לצאת `-12`)
- בדיקת שמע: הזזת פלייבק ב-±2 ו-±3 — האם התופים נשארו חדים?
- בדיקת אורך: כל הפלטים חייבים להיות זהים באורך למקור עד רמת הדגימה.

**Definition of Done:** ההמלצה נכונה ב-5 מתוך 5 שירי הבדיקה לפי שיפוט אנושי;
הזזת פלייבק ב-3 חצאי טונים נשמעת מקובלת; אורכים מדויקים.
**מה עוד לא עושים:** המרת קול בפועל.

## Phase 5 — מנוע המרת הקול

**מטרה:** להמיר את הווקאל לקול היעד, בשליטה מלאה.

**מה בונים:**
- `conversion/rvc/` — חילוץ קוד ה-inference של RVC v2 למודול נקי ומתועד שלנו
- טעינת מודלים, ניהול זיכרון, ניקוי אחרי הרצה
- כל הפרמטרים: `f0_up_key`, `index_rate`, `protect`, `rms_mix_rate`, `filter_radius`, `formant_shift`
- עיבוד בקטעים (chunks) עם חפיפה והצלבה חלקה — בלי תפרים נשמעים
- `voices/` — קטלוג הקולות: ייבוא, אימות תקינות, מניפסט, פרופיל, אישור הרשאה
- חיבור לשלבים 2–4: **צינור CLI מלא מקצה לקצה**

**קבצים עיקריים:** `src/svc_engine/conversion/`, `src/svc_engine/voices/`

**איך בודקים:**
```bash
svc convert "song.mp3" --voice yossi --quality balanced --out cover.wav
```
זו הפעם הראשונה שמקבלים קאבר שלם. מאזינים.

**Definition of Done:** צינור מלא עובד על 5 שירי בדיקה בלי קריסה;
אין תפרים נשמעים בין chunks; ייבוא קול מקובץ zip עובד; VRAM משתחרר אחרי כל הרצה.
**מה עוד לא עושים:** מיקס מתוחכם, ממשק.

## Phase 6 — תיקונים ומיקס

**מטרה:** להפוך את הפלט הגולמי לתוצאה שנשמעת מקצועית.

**מה בונים:**
- `postfx/repair.py` — הסרת clicks ו-artifacts
- `postfx/melody_check.py` — מתאם F0 מול המקור + תיקון עדין אם צריך
- `postfx/envelope.py` — התאמת מעטפת העוצמה לביצוע המקורי
- `postfx/deess.py` — de-esser עדין
- `postfx/ambience.py` — **החזרת שכבת ההדהוד המקורית**
- `postfx/mix.py` — איזון LUFS בין ווקאל לפלייבק, סכימה, לימיטר
- `postfx/export.py` — WAV 24-bit + MP3 320, שמות קבצים נקיים

**קבצים עיקריים:** `src/svc_engine/postfx/`

**איך בודקים:** השוואת A/B מול הפלט של Phase 5. האם הקול "יושב" במיקס?
מדידת LUFS סופי. בדיקת clipping.

**Definition of Done:** LUFS סופי בטווח ±0.5 מהיעד; אין clipping;
בשיפוט אנושי — התוצאה טובה מובהקת מהפלט של Phase 5 ב-5 מתוך 5 שירים.
**מה עוד לא עושים:** ממשק.

## Phase 7 — ניהול משימות ושרידות

**מטרה:** שהתוכנה תשרוד את המציאות.

**מה בונים:**
- `jobs/runner.py` — גרף צעדים, מעקב התקדמות
- `jobs/cache.py` — cache לפי hash של קלט+פרמטרים
- `jobs/cancel.py` — ביטול נקי + הרג בכוח כגיבוי
- `jobs/recovery.py` — שמירת מצב וחידוש אחרי קריסה
- `projects/` — שמירה/טעינה של פרויקט
- `history/` — היסטוריית עבודות ב-SQLite
- ניקוי אוטומטי של קבצים זמניים + מדיניות גודל cache

**קבצים עיקריים:** `src/svc_engine/jobs/`, `src/svc_engine/projects/`

**איך בודקים:** להרוג את התהליך באמצע כל אחד מהשלבים ולוודא שהוא מתאושש נכון.
לשנות פרמטר אחד ולוודא ששלבים שלא הושפעו לא רצים שוב.

**Definition of Done:** הריגה באמצע כל שלב → התאוששות מוצלחת; ביטול תוך פחות מ-3 שניות;
cache חוסך זמן בהרצה שנייה; אין קבצים זמניים יתומים.
**מה עוד לא עושים:** ממשק.

## Phase 8 — הממשק הגרפי (מצב פשוט) 🎯 סוף ה-MVP

**מטרה:** שתוכל להשתמש בתוכנה בלי שורת פקודה, בכלל.

**מה בונים:**
- `svc_app/design/` — ערכת עיצוב: צבעים, טיפוגרפיה עברית, QSS, מצב כהה/בהיר
- `svc_app/engine_client.py` — הפעלת המנוע כתהליך נפרד + תקשורת + התקדמות
- מסכים: שיר → קול → איכות → עיבוד → המלצה → Preview → תוצאה
- רכיבים: אזור גרירה, כרטיס קול, נגן A/B, פס התקדמות, כרטיס המלצה
- `i18n/` — כל המחרוזות בעברית + טבלת תרגום השגיאות
- RTL מלא + טיפול בטקסט מעורב

**קבצים עיקריים:** `src/svc_app/`

**איך בודקים:** משתמש שלא ראה את התוכנה מקבל שיר וקול ומצליח להוציא קאבר בלי הסבר.

**Definition of Done:** מסלול מלא בממשק בלי לגעת בטרמינל; שגיאות מוצגות בעברית עם פעולה מוצעת;
ביטול עובד מהממשק; Preview עובד; RTL תקין בכל מסך.
**מה עוד לא עושים:** אימון קולות, מצב מתקדם, installer.

## Phase 9 — ניהול קולות ואשף האימון

**מטרה:** שתוכל ליצור קול חדש משלך, בלי להבין כלום ב-AI.

**מה בונים:**
- מסך "קולות": רשת כרטיסים, הוספה/הסרה/שינוי שם/תמונה/דוגמה/בדיקת תקינות
- `training/dataset.py` — הכנת דאטה אוטומטית: הפרדה, DeReverb, Denoise, חיתוך שקטים, פריסה לקטעים
- `training/quality.py` — בדיקת איכות: יחס רעש, clipping, משך כולל, עקביות דובר
- `training/trainer.py` — עטיפה לאימון RVC עם מודל בסיס TITAN
- אשף ב-5 שלבים: **הוסף הקלטות → בדיקת איכות → ניקוי → אימון → הקול מוכן**
- הערכת זמן אימון מדויקת + אפשרות עצירה והמשך
- חישוב אוטומטי של פרופיל המנעד בסיום
- **מסך אישור הרשאה** לפני יצירת כל קול

**קבצים עיקריים:** `src/svc_engine/training/`, `src/svc_app/screens/voices/`

**איך בודקים:** לאמן קול מ-15 דקות הקלטה דרך הממשק בלבד, ואז להשתמש בו לקאבר.

**Definition of Done:** אימון מקצה לקצה דרך הממשק; המשתמש מקבל משוב ברור על איכות
החומר לפני האימון; אפשר לעצור ולהמשיך; פרופיל מנעד מחושב אוטומטית.

## Phase 10 — מצב מתקדם ומעבדת הבנצ'מרק

**מטרה:** שליטה מלאה למי שרוצה, ויכולת להשוות אפשרויות במקום לנחש.

**מה בונים:**
- פאנל מצב מתקדם עם כל הפרמטרים + הסבר ⓘ לכל אחד
- **כוונון אוטומטי**: הרצת 3–4 קומבינציות על קטע ה-Preview ובחירת המנצחת לפי מדדים
- `benchmark/` — מערכת השוואה: הרצת מטריצת ניסויים, שמירת זמנים/VRAM/כשלים/הגדרות
- מסך השוואת A/B בממשק עם מעבר מיידי בין גרסאות
- מנוע המרה שני (zero-shot) כניסוי — לתרחיש "יש לי רק דגימה קצרה"

**Definition of Done:** אפשר להריץ מטריצת השוואה ולקבל טבלת תוצאות + האזנת A/B;
הכוונון האוטומטי בוחר לפחות כמו בחירה ידנית ב-4 מתוך 5 מקרים.

## Phase 11 — אריזה, installer ועדכונים

**מטרה:** Download → Install → Open.

**מה בונים:**
- סביבת Python מוטבעת + build של האפליקציה
- `Inno Setup` — installer בעברית, קיצור דרך, הסרה נקייה
- אשף הפעלה ראשונה: זיהוי GPU → הורדת PyTorch → הורדת מודלים → בדיקת תקינות
- שיקוף כל המודלים לריפו HuggingFace פרטי שלנו
- בדיקת עדכונים + עדכון בתוך האפליקציה
- CI: בניית installer אוטומטית על כל תגית

**איך בודקים:** התקנה על מכונה וירטואלית נקייה של Windows 11 בלי Python, בלי CUDA, בלי כלום.

**Definition of Done:** התקנה נקייה → קאבר ראשון עובד, בלי שהמשתמש ראה טרמינל ולו פעם אחת;
הסרה מנקה הכול; installer מלא (offline) קיים גם הוא.

## מה אחרי v1.0 (רעיונות, לא התחייבות)

- המרת ווקאלים מלווים בנפרד (מקהלה בקול היעד)
- עיבוד אצווה (batch) של כמה שירים
- ייצוא stems ל-DAW
- מודל zero-shot בשל יותר כשיופיע כזה עם תמיכת Windows
- שיפור הרמוניות ותיקון אינטונציה
