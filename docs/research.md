# מחקר טכנולוגי — המרת קול בשירים

**תאריך המחקר:** 16 באוגוסט 2026
**מטרה:** לבחור את הטכנולוגיות הטובות ביותר שקיימות היום, בחינם ובקוד פתוח, שרצות מקומית על Windows 11 עם RTX 2000 Ada (16GB VRAM).

## 0. מילון מונחים (לקרוא פעם אחת, ואז הכול ברור)

| מונח | מה זה בעברית פשוטה |
|------|---------------------|
| **F0** | הגובה הבסיסי של הקול — בערך איזה תו הזמר שר בכל רגע. |
| **Pitch** | גובה הצליל. אותו דבר כמו F0 בהקשר שלנו. |
| **Semitone / חצי טון** | הצעד הקטן ביותר במוזיקה. 12 חצאי טונים = אוקטבה שלמה. |
| **Stem** | "שכבה" של השיר אחרי שמפרידים אותו — למשל רק השירה, או רק התופים. |
| **Separation / הפרדה** | תהליך שמפצל שיר מוקלט חזרה לשכבות (שירה, בס, תופים, שאר). |
| **VC / Voice Conversion** | המרת קול: לוקחים הקלטה של קול אחד ומוציאים את אותה שירה בקול אחר. |
| **SVC** | Voice Conversion שמותאם במיוחד לשירה (ולא רק לדיבור). |
| **Timbre / גוון** | ה"צבע" של הקול — מה שגורם לנו לזהות שזה יוסי ולא דני, גם כשהם שרים את אותו תו. |
| **Formant** | תדרים מודגשים שנוצרים מצורת הגרון והפה. הם מה שקובע אם קול נשמע "גדול" (גברי) או "קטן" (ילדותי). |
| **Inference** | ההרצה של מודל AI מאומן על קלט חדש. "הפעלת המודל". |
| **Checkpoint** | קובץ המשקולות של המודל — ה"מוח" השמור שלו. |
| **VRAM** | הזיכרון של כרטיס המסך. אצלך: 16GB. |
| **Zero-shot** | מודל שמצליח לחקות קול מדוגמה קצרה, בלי לאמן אותו מראש על אותו קול. |
| **Ensemble** | להריץ כמה מודלים על אותו קלט ולשלב את התוצאות כדי לקבל תוצאה טובה יותר. |
| **SDR** | מדד איכות להפרדה. ככל שהמספר גבוה יותר — ההפרדה נקייה יותר. נמדד ב-dB. |
| **LUFS** | מדד עוצמת שמע תפיסתית. ככה מיישרים ווליום בין קבצים בצורה נכונה. |
| **Vocoder** | הרכיב שממיר ייצוג פנימי של קול בחזרה לגלי קול שאפשר לשמוע. |

## 1. סיכום מנהלים — ההמלצה בשורה אחת

> **הפרדה:** BS-Roformer / Mel-Band Roformer (הדור החדש) דרך ספריית Python מתוחזקת, עם אפשרות Ensemble במצב "איכות מרבית".
> **המרת קול:** RVC v2 (מודל מאומן לכל קול) כברירת מחדל, בעטיפה שלנו — לא Gradio ולא WebUI.
> **הפתרון לבעיית המנעד:** מנוע החלטה שמפריד בין "הזזת אוקטבות" (חינם מבחינה מוזיקלית) לבין "שינוי סולם" (עולה באיכות הנגינה) — פירוט מלא בפרק 4.
> **הטכנולוגיה של התוכנה:** Python + PySide6 (Qt), עם תהליך עבודה נפרד למנוע ה-AI.

## 2. הפרדת שירה ממוזיקה (Separation)

### 2.1 למה זה השלב הכי קריטי

אם בשלב ההפרדה נשארים שאריות של כלי נגינה בתוך הווקאל, מודל המרת הקול "ילמד" אותן
כאילו הן חלק מהקול וייצר רעשים מוזרים. איכות ההמרה לא יכולה להיות טובה יותר מאיכות ההפרדה.
לכן זה השלב שבו כדאי להשקיע הכי הרבה זמן מחשוב.

### 2.2 מצב הטכנולוגיה ב-2026

הדור הנוכחי של מודלי הפרדה מבוסס על ארכיטקטורת **RoFormer** (טרנספורמר שמעבד את
הצליל גם לאורך הזמן וגם לאורך התדרים). שתי משפחות עיקריות:

- **BS-Roformer** — מחלק את התדרים ל"פסים" (Band Split). מקורי מ-ByteDance, זכה בתחרות SDX23.
- **Mel-Band Roformer** — מחלק את התדרים לפי סקאלת Mel (קרובה יותר לאיך שהאוזן שומעת). מוסיף בממוצע כ-0.5dB על BS-Roformer בווקאל.

מ-2026 יש גם וריאנט חדש, **BS PolarFormer**, שמחליף את ה-embedding הסיבובי ב-embedding
קוטבי ומאפשר הקשר ארוך יותר (51M פרמטרים, 60 פסי תדר).

### 2.3 מספרים אמיתיים (לוח התוצאות של MVSEP, Multisong benchmark)

| מודל | SDR ווקאל | SDR פלייבק | זמין להורדה מקומית? |
|------|-----------|------------|---------------------|
| BS Roformer 124 bands (MVSep, 2026.07) | 12.33 | 18.64 | ✗ שירות ענן בלבד |
| BS PolarFormer 124 bands (MVSep, 2026.06) | 12.02 | 18.33 | ✗ שירות ענן בלבד |
| **BS-Roformer_Leap (pcunwa / unwa)** | **11.74** | 17.53 | ✓ כן, HuggingFace |
| BS PolarFormer Vocals (2026.05) | 11.76 | 18.07 | ✓ כן (bgkb/bs_polarformer) |
| Mel-Band Roformer (Kim / KimberleyJensen) | ~10.98 | — | ✓ כן, הכי נפוץ ויציב |
| MDX23C | 10.17 | — | ✓ כן |
| HTDemucs4 FT | 8.78 | — | ✓ כן |

**המשמעות:** הפער בין המודל הכי טוב בענן (12.33) למודל הכי טוב שאפשר להוריד (11.7–11.8)
הוא כ-0.5dB. זה פער קטן — כלומר **אנחנו לא מפסידים כמעט כלום מזה שאנחנו עובדים מקומית**.

### 2.4 איזו ספריה משתמשים בה בפועל

| אפשרות | יתרונות | חסרונות | החלטה |
|--------|---------|---------|-------|
| **audio-separator** (nomadkaraoke, MIT, v0.44.5) | בוגרת, 1300+ כוכבים, `pip install`, הורדת מודלים אוטומטית, תומכת MDX/VR/Demucs/MDXC-Roformer, פעילה | קטלוג המודלים לפעמים מפגר אחרי החדשים ביותר | ✅ **מנוע ברירת מחדל** |
| **pymss** (MIT, v2.1.3) | תומכת ב-12 ארכיטקטורות כולל BS/Mel Conformer, Apollo, SCNet; טוענת קונפיגים ישירות מ-HuggingFace | צעירה (44 כוכבים), פחות מוכחת | ✅ **מנוע שני**, לגישה למודלים הכי חדשים |
| **MSST** (ZFTurbo, MIT) | קוד המקור של רוב המודלים; הכי עדכני | ספריית אימון, לא ספריית inference נוחה | 🔧 מקור לקונפיגים ולמודלים |
| **MSST-WebUI** | ממשק נוח, קטלוג מודלים ענק | רישיון **AGPL-3.0** — מדביק את הקוד שלנו | ❌ לא נשתמש בקוד, רק כמקור מידע |
| **UVR5 (GUI)** | הכי מוכר בקהילה | לא עודכן מאז מרץ 2025 | ❌ לא רלוונטי כספריה |

**החלטה:** נבנה שכבת הפשטה `SeparationBackend` עם שני מימושים (audio-separator, pymss).
כך אם מודל חדש יוצא — מוסיפים אותו בלי לגעת בשאר התוכנה.

### 2.5 שרשרת ההפרדה המומלצת

התוכנה תריץ בין 1 ל-4 שלבי הפרדה, לפי רמת האיכות שנבחרה:

```
שיר מקורי (WAV 44.1kHz stereo)
   │
   ├─[1] הפרדה ראשית: ווקאל ↔ פלייבק          ← תמיד
   │
   ├─[2] הפרדת ליווי קולי: ליד ↔ ווקאלים מלווים  ← אוטומטי אם מזוהים ווקאלים מלווים
   │
   ├─[3] DeReverb + DeEcho על הליד             ← אוטומטי אם מזוהה הדהוד חזק
   │        └─ תוצר לוואי חשוב: "שכבת ההדהוד" נשמרת בנפרד!
   │
   └─[4] Denoise עדין                          ← רק במצב "איכות מרבית"
```

**רעיון מפתח:** שלב 3 לא רק מנקה — הוא גם **שומר את ההדהוד המקורי כשכבה נפרדת**.
אחרי ההמרה נחזיר את אותה שכבה בדיוק אל הקול החדש. כך הקול החדש "יושב" באותו חלל
אקוסטי כמו המקור, בלי שנצטרך להמציא reverb מלאכותי.

### 2.6 האם Ensemble שווה את זה?

**כן, אבל רק במצב "איכות מרבית".** שילוב של 2–3 מודלים (ממוצע או min-magnitude)
נותן בדרך כלל שיפור של 0.2–0.4dB ומפחית artifacts ייחודיים למודל בודד.
העלות: פי 2–3 זמן עיבוד. במצב "מאוזן" נריץ מודל אחד טוב — זה מספיק ב-90% מהמקרים.

### 2.7 רמות איכות שנציע למשתמש

| רמה | מה קורה | זמן משוער לשיר של 4 דקות* |
|-----|---------|---------------------------|
| **מהיר** | מודל Mel-Band Roformer יחיד, overlap נמוך | ~1–2 דקות |
| **מאוזן** (ברירת מחדל) | BS-Roformer מוביל + DeReverb לפי צורך | ~3–5 דקות |
| **איכות מרבית** | Ensemble של 2–3 מודלים + כל שלבי הניקוי | ~10–18 דקות |

\* הערכה על RTX 2000 Ada. יאומת בפועל בשלב 2 של הפיתוח.

## 3. המרת הקול עצמה (Voice Conversion)

### 3.1 המועמדים שנבדקו

| פתרון | רישיון | מצב תחזוקה | סוג | הערכה |
|-------|--------|------------|-----|-------|
| **RVC v2** (RVC-Project) | MIT | ✅ פעיל (אוגוסט 2026), 37K כוכבים | מודל מאומן לכל קול | **הכי בוגר, הכי נשלט, הכי מתועד** |
| **Applio** (פורק של RVC) | MIT | 🟡 מצב תחזוקה — "לא יקבל עדכונים תכופים" | מודל מאומן | קוד נקי ונוח לשימוש כספריה |
| **codename-rvc-fork-4** | — | ✅ פעיל | מודל מאומן | vocoders חדשים (RefineGAN, RingFormer, PCPH-GAN) |
| **Seed-VC** (Plachtaa) | GPL-3.0 | ❌ **הריפו נסגר (archived) באפריל 2025** | Zero-shot | סיכון תחזוקה גבוה + רישיון מדביק |
| **YingMusic-SVC** (GiantAILab) | MIT | 🟡 דצמבר 2025, קהילה קטנה | Zero-shot לשירה | מבטיח מאוד, אבל בנוי להרצה על Linux |
| **HQ-SVC** | לא מוגדר | 🟡 יוני 2026 | Zero-shot | **דורש Linux/WSL** — לא מתאים לנו |
| **DDSP-SVC 6.0** | MIT | ✅ פעיל (אוגוסט 2026) | מודל מאומן | קל מאוד על החומרה, איכות טובה אבל בד"כ לא ברמת RVC בדמיון גוון |
| **so-vits-svc** | AGPL | ❌ נסגר ב-2023 | מודל מאומן | לא רלוונטי |

### 3.2 ההחלטה: RVC v2 כבסיס, ולמה

**למה RVC ולא Zero-shot?**

1. **איכות דמיון גוון.** מודל שאומן על 15–30 דקות מהקול היעד נותן דמיון גבוה בהרבה
   ממודל zero-shot שמקבל דוגמה של 10 שניות. בשירה — שבה יש הרבה יותר ואריאציה מאשר בדיבור —
   הפער הזה גדול.
2. **יציבות ותחזוקה.** RVC-Project פעיל, MIT, ועם קהילה עצומה. אם משהו נשבר, יש תשובות.
   Seed-VC נסגר, HQ-SVC דורש Linux, YingMusic-SVC בן חצי שנה עם 155 כוכבים.
3. **שליטה.** RVC נותן בדיוק את הידיות שאנחנו צריכים לבעיית המנעד:
   `f0_up_key` (הזזת חצאי טונים), `index_rate` (כמה להיצמד לחומר האימון),
   `protect` (הגנה על עיצורים), `rms_mix_rate` (שימור הדינמיקה של המקור).
4. **מהירות.** ההמרה עצמה מהירה מאוד — דקות בודדות לשיר שלם על ה-GPU שלך.

**מה עושים עם Zero-shot אז?**
נשאיר לו מקום בארכיטקטורה כ"מנוע שני" (Phase 10+), לתרחיש "יש לי רק דגימה קצרה ואני
רוצה לשמוע איך זה נשמע". אבל **לא ב-MVP**.

### 3.3 מודל בסיס (Pretrained) לאימון

לאימון קולות חדשים נשתמש ב-**TITAN** (blaise-tk/TITAN) — מודל בסיס איכותי במיוחד
ל-RVC, שמאפשר להגיע לתוצאה טובה בפחות epochs ועם פחות דאטה מהבסיס הרשמי.

### 3.4 Vocoder

ברירת מחדל: **HiFi-GAN-NSF** (הסטנדרטי ב-RVC, יציב ותואם לכל המודלים הקיימים בעולם).
נבדוק בשלב הבנצ'מרק אם **RefineGAN** נותן שיפור מורגש — הוא נותן איכות גבוהה יותר
אבל מייצר מודלים שתואמים רק חלקית לכלים אחרים.

### 3.5 הפרמטרים ש-RVC נותן לנו וכיצד נגדיר אותם אוטומטית

| פרמטר | מה הוא עושה (עברית פשוטה) | ברירת מחדל אוטומטית |
|-------|---------------------------|---------------------|
| `f0_method` | איך מזהים את גובה הצליל | `rmvpe` (הכי טוב לשירה) |
| `f0_up_key` | בכמה חצאי טונים להזיז את הקול | מחושב ע"י מנוע המנעד (פרק 4) |
| `index_rate` | כמה להיצמד לגוון של חומר האימון | 0.6 — 0.75 |
| `protect` | הגנה על עיצורים ונשימות מפני עיוות | 0.33 |
| `rms_mix_rate` | כמה לשמר את הדינמיקה (חזק/חלש) של הביצוע המקורי | 0.25 |
| `filter_radius` | החלקה של עקומת הגובה | 3 |
| `formant_shift` | תיקון "גודל" הקול כשיש הזזת גובה גדולה | מחושב אוטומטית |

## 4. ⭐ הלב של הפרויקט: הפתרון לפער המנעד

זו הנקודה שביקשת להתייחס אליה במיוחד, וזו גם הנקודה שבה רוב הכלים הקיימים נכשלים.

### 4.1 מה הבעיה בדיוק

אישה שרה שיר בטווח של, נניח, לה3 עד רה5. גבר ממוצע שר בנוחות בין סול2 לסול3 בערך.
אם פשוט נחליף גוון בלי לגעת בגובה — נקבל גבר ששר בגובה של אישה. התוצאה:
קול פלסטיק, "פאלצטו מלאכותי", או צליל חנוק ולא טבעי.

### 4.2 התובנה המרכזית — לא כל הזזה עולה אותו דבר

יש הבדל עצום בין שני סוגי הזזה:

**(א) הזזה של אוקטבה שלמה (12, 24 חצאי טונים) — "חינם" מבחינה מוזיקלית.**
תו והתו שאוקטבה מתחתיו הם *אותו תו* מבחינה הרמונית. אם נוריד את השירה בדיוק ב-12
חצאי טונים והפלייבק יישאר בדיוק כמו שהוא — **הכול עדיין בסולם, הכול עדיין מתאים.**
זו בדיוק מה שקורה כשגבר שר שיר של אישה בקריוקי.

**(ב) הזזה שאינה כפולה של 12 — משנה את הסולם של השיר.**
אם נוריד את השירה ב-3 חצאי טונים, חייבים להוריד גם את כל הפלייבק ב-3, אחרת השירה
תהיה "לא בסולם" ותישמע צורמת. הורדת הפלייבק דורשת עיבוד שפוגע קצת באיכות הנגינה.

### 4.3 האלגוריתם

```
כל הזזה s (בחצאי טונים) מתפרקת ל:   s = 12·k + r
                                      ↑        ↑
                            אוקטבות (חינם)   שינוי סולם (עולה באיכות)
```

**שלב 1 — פרופיל הקול המקורי בשיר.**
מריצים RMVPE על הווקאל המופרד ומקבלים עקומת F0. ממנה מחשבים (ביחידות MIDI, כלומר חצאי טונים):
`p05, p25, p50 (חציון), p75, p95`, וגם `min`, `max`. משקללים לפי אנרגיה ומשך —
תו ארוך וחזק "נחשב" יותר מקישוט של 50 מילישניות.

**שלב 2 — פרופיל קול היעד.**
כל מודל קול במערכת שומר פרופיל F0 שנמדד מחומר האימון שלו:
- `comfort_low = p05`, `comfort_high = p95` (הטווח הנוח)
- `abs_low`, `abs_high` (הקצוות שהמודל בכלל ראה)

זה קריטי: מודל שאומן רק על דיבור לא יודע לשיר גבוה. מודל שאומן על שירה — כן.
התוכנה תמדוד את זה אוטומטית בזמן ייבוא/אימון הקול.

**שלב 3 — פונקציית עלות.**
עבור כל מועמד `s` בטווח [-24, +24]:

```
cost(s) =  w₁ · מסת_תווים_מחוץ_לטווח_הנוח(s)
         + w₂ · מסת_תווים_מחוץ_לטווח_המוחלט(s)     ← קנס כבד
         + w₃ · |חציון_מוזז(s) − חציון_היעד|
         + w₄ · קנס_פלייבק(|r|)                     ← r = s mod 12, ממופה ל-[-6..+5]
         + w₅ · קנס_פורמנטים(|s|)                   ← הזזות ענק נשמעות מלאכותיות
```

**המפתח:** `קנס_פלייבק` תלוי **רק ב-r**, לא ב-s. הזזה של 12 או 24 לא עולה כלום בפלייבק.

**שלב 4 — הצגה למשתמש בעברית פשוטה.**
מציגים את 2–3 האפשרויות הכי טובות, למשל:

> ✅ **מומלץ:** להוריד את השירה באוקטבה שלמה (12 חצאי טונים).
> המוזיקה נשארת בדיוק כמו שהיא, בלי שום פגיעה באיכות.
>
> **אפשרות נוספת:** להוריד 14 חצאי טונים — זה יתאים את השיר עוד קצת יותר טוב לקול שבחרת,
> אבל אז צריך להוריד גם את המוזיקה ב-2 חצאי טונים. הפגיעה באיכות הנגינה תהיה קטנה מאוד.

### 4.4 טריק איכות: לא לגעת בתופים

כשצריך להזיז את הפלייבק (כלומר `r ≠ 0`), **אסור להזיז את התופים.**
לתופים אין גובה מוגדר, והזזת גובה שלהם הורסת את החדות שלהם (ה-transients).

לכן: כשצריך שינוי סולם, מפרידים את הפלייבק ל-3 שכבות (בס / תופים / שאר),
מזיזים רק את הבס והשאר, ומחברים בחזרה עם התופים המקוריים.
זה שיפור איכות משמעותי שרוב הכלים לא עושים.

## 6. אחרי ההמרה: תיקונים ומיקס

```
קול מומר (יבש)
   │
   ├─ 1. ניקוי artifacts — הסרת clicks, פיקים חריגים
   ├─ 2. בדיקת מנגינה — מתאם F0 מול המקור; תיקון עדין אם צריך
   ├─ 3. התאמת מעטפת עוצמה למקור (שימור הדינמיקה של הביצוע)
   ├─ 4. De-esser עדין (RVC נוטה לפעמים להדגיש ש' ו-ס')
   ├─ 5. התאמת ספקטרום (EQ match) לאופי הווקאל המקורי — אופציונלי
   ├─ 6. החזרת שכבת ההדהוד שנשמרה בשלב ההפרדה  ← זה מה שגורם לזה "לשבת" במיקס
   └─ 7. נרמול LUFS של הווקאל
   │
   └──► מיקס: ווקאל + פלייבק (+ ווקאלים מלווים) → לימיטר → ייצוא
```

**כלים:**
- מדידת LUFS: `pyloudnorm` (MIT) — מדויק ותקני (ITU-R BS.1770).
- אפקטים (EQ, קומפרסור, לימיטר, reverb): `pedalboard` של Spotify — **אבל הוא GPL-3.0.**
  חלופה: לממש EQ/קומפרסור/לימיטר בסיסיים ב-numpy/scipy (לא מסובך) ולהימנע מהתלות.
- התאמת מאסטרינג אוטומטית: `matchering` (GPL-3.0) — נחמד אבל לא הכרחי, ורישיונו בעייתי.
  **החלטה:** לא נכניס אותו ל-MVP.
- דגימה מחדש (resampling): `soxr` — איכות VHQ, קריטי כי RVC עובד ב-40k/48k והשיר ב-44.1k.

**יעד עוצמה:** ‎-14 LUFS ברירת מחדל (סטנדרט סטרימינג), עם אפשרות ל-‎-9 LUFS ("חזק").

## 14. מה בחרנו — סיכום ה-Pipeline המומלץ

```
┌────────────────────────────────────────────────────────────────┐
│ 1. קליטה      ffmpeg → WAV 44.1kHz/stereo/float32              │
│ 2. הפרדה      Roformer (BS/Mel-Band) → ווקאל + פלייבק          │
│    2b. ליווי  מודל karaoke → ליד + ווקאלים מלווים   [לפי צורך] │
│    2c. הדהוד  DeReverb → ליד יבש + שכבת הדהוד       [לפי צורך] │
│ 3. ניתוח      RMVPE → עקומת F0 → פרופיל מנעד + זיהוי סולם      │
│ 4. החלטה      מנוע המנעד → s = 12k + r  (+ הסבר בעברית)        │
│ 5. הזזה       פלייבק: אם r≠0 → פיצול 3 שכבות, הזזה בלי תופים   │
│ 6. המרה       RVC v2 (f0_up_key = s, RMVPE, index/protect/rms)  │
│ 7. תיקון      artifacts → בדיקת מנגינה → מעטפת → de-ess         │
│ 8. החזרה      החזרת שכבת ההדהוד המקורית                         │
│ 9. מיקס       LUFS balance → סכימה → לימיטר                     │
│ 10. ייצוא     WAV 24-bit + MP3 320kbps                          │
└────────────────────────────────────────────────────────────────┘
```
