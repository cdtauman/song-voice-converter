**תאריך המחקר:** 16 באוגוסט 2026
**עודכן:** 16 באוגוסט 2026 — סבב ביקורת ראשון (ראה [changelog.md](changelog.md))
**מטרה:** לבחור את הטכנולוגיות הטובות ביותר שקיימות היום, בחינם ובקוד פתוח, שרצות מקומית על Windows 11 עם RTX 2000 Ada (16GB VRAM).

## 0. מילון מונחים (לקרוא פעם אחת, ואז הכול ברור)

| מונח | מה זה בעברית פשוטה |
|------|---------------------|
| **F0** | הגובה הבסיסי של הקול — בערך איזה תו הזמר שר בכל רגע. |
| **Pitch** | גובה הצליל. אותו דבר כמו F0 בהקשר שלנו. |
| **Semitone / חצי טון** | הצעד הקטן ביותר במוזיקה. 12 חצאי טונים = אוקטבה שלמה. |
| **Stem** | "שכבה" של השיר אחרי שמפרידים אותו — למשל רק השירה, או רק התופים. |
| **Separation / הפרדה** | תהליך שמפצל שיר מוקלט חזרה לשכבות (שירה, בס, תופים, שאר). |
| **VC / Voice Conversion** | המרת קול: לוקחים הקלטה של קול אחד ומוציאים את אותה שירה בקול אחר. |
| **SVC** | Voice Conversion שמותאם במיוחד לשירה (ולא רק לדיבור). |
| **Timbre / גוון** | ה"צבע" של הקול — מה שגורם לנו לזהות שזה יוסי ולא דני, גם כשהם שרים את אותו תו. |
| **Formant** | תדרים מודגשים שנוצרים מצורת הגרון והפה. הם מה שקובע אם קול נשמע "גדול" (גברי) או "קטן" (ילדותי). |
| **Inference** | ההרצה של מודל AI מאומן על קלט חדש. "הפעלת המודל". |
| **Checkpoint** | קובץ המשקולות של המודל — ה"מוח" השמור שלו. |
| **VRAM** | הזיכרון של כרטיס המסך. אצלך: 16GB. |
| **Zero-shot** | מודל שמצליח לחקות קול מדוגמה קצרה, בלי לאמן אותו מראש על אותו קול. |
| **Ensemble** | להריץ כמה מודלים על אותו קלט ולשלב את התוצאות כדי לקבל תוצאה טובה יותר. |
| **SDR** | מדד איכות להפרדה. ככל שהמספר גבוה יותר — ההפרדה נקייה יותר. נמדד ב-dB. |
| **LUFS** | מדד עוצמת שמע תפיסתית. ככה מיישרים ווליום בין קבצים בצורה נכונה. |
| **Vocoder** | הרכיב שממיר ייצוג פנימי של קול בחזרה לגלי קול שאפשר לשמוע. |
| **Spike** | ניסוי טכני קצר שמטרתו לענות על שאלה אחת לפני שבונים על התשובה. |

## 1. סיכום מנהלים — ההמלצה בשורה אחת

> **הפרדה:** BS PolarFormer / Mel-Band Roformer (הדור החדש), דרך ספריית Python מתוחזקת, עם אפשרות Ensemble במצב "איכות מרבית".
> **המרת קול:** RVC v2 כמנוע ה-MVP — **מאחורי מתאם `ConversionBackend` שמונע נעילה אליו**.
> **הפתרון לבעיית המנעד:** מנוע החלטה שמפריד בין "הזזת אוקטבות" (חינם מבחינת הסולם של הפלייבק) לבין "שינוי סולם" (עולה באיכות הנגינה) — פירוט מלא בפרק 4.
> **הטכנולוגיה של התוכנה:** Python + PySide6 (Qt), עם תהליך עבודה נפרד למנוע ה-AI.
> **גרסאות התלויות:** **לא ננעלות מראש.** נקבעות ב-Compatibility Spike של Phase 1 על המחשב שלך.

## 2. הפרדת שירה ממוזיקה (Separation)

### 2.1 למה זה השלב הכי קריטי

אם בשלב ההפרדה נשארים שאריות של כלי נגינה בתוך הווקאל, מודל המרת הקול "ילמד" אותן
כאילו הן חלק מהקול וייצר רעשים מוזרים. איכות ההמרה לא יכולה להיות טובה יותר מאיכות ההפרדה.
לכן זה השלב שבו כדאי להשקיע הכי הרבה זמן מחשוב.

### 2.2 מצב הטכנולוגיה ב-2026

הדור הנוכחי של מודלי הפרדה מבוסס על ארכיטקטורת **RoFormer** (טרנספורמר שמעבד את
הצליל גם לאורך הזמן וגם לאורך התדרים). שלוש משפחות עיקריות:

- **BS-Roformer** — מחלק את התדרים ל"פסים" (Band Split). מקורי מ-ByteDance, זכה בתחרות SDX23.
- **Mel-Band Roformer** — מחלק את התדרים לפי סקאלת Mel (קרובה יותר לאיך שהאוזן שומעת). מוסיף בממוצע כ-0.5dB על BS-Roformer בווקאל.
- **BS PolarFormer** — וריאנט מ-2026 שמחליף את ה-embedding הסיבובי ב-embedding קוטבי ומאפשר הקשר ארוך יותר (51M פרמטרים, 60 פסי תדר).

### 2.3 מספרים אמיתיים, עם רישוי מאומת

לוח התוצאות של MVSEP (Multisong benchmark), אוגוסט 2026. **עמודת הרישיון אומתה מול ה-API של HuggingFace ב-16.8.2026.**

| מודל | SDR ווקאל | להורדה? | רישיון מאומת | הערה |
|------|-----------|---------|--------------|------|
| BS Roformer 124 bands (MVSep) | 12.33 | ✗ | — | שירות ענן בתשלום |
| BS PolarFormer 124 bands (MVSep) | 12.02 | ✗ | — | שירות ענן בתשלום |
| **BS PolarFormer Vocals** (`bgkb/bs_polarformer`) | **11.76** | ✓ | **MIT** ✅ | **ברירת המחדל המומלצת** |
| BS-Roformer Leap (`pcunwa/BS-Roformer-Leap`) | 11.74 | ✓ | **אין הצהרה** ⚠️ | שימוש פרטי בלבד עד לבירור |
| Mel-Band Roformer Kim | ~10.98 | ✓ | טעון אימות | הכי נפוץ ויציב |
| MDX23C | 10.17 | ✓ | MIT (UVR) | דור קודם |
| HTDemucs4 FT | 8.78 | ✓ | MIT | לפיצול הפלייבק לשכבות |

> **ממצא חשוב שמבטל חשש קודם.** בסבב הקודם הנחתי שגרסה הניתנת להפצה תחייב ירידה באיכות,
> כי המודלים הטובים חסרי רישיון. **הבדיקה הראתה שההנחה שגויה:**
> BS PolarFormer הוא MIT **וגם** מדורג מעט **מעל** BS-Roformer Leap (11.76 מול 11.74).
> **אין שום התנגשות בין איכות לרישוי בשלב ההפרדה.**

**המשמעות הכללית:** הפער בין המודל הכי טוב בענן (12.33) למודל MIT שאפשר להוריד (11.76)
הוא כ-0.6dB. פער קטן — **כמעט לא מפסידים כלום מעבודה מקומית.**

### 2.4 איזו ספריה משתמשים בה בפועל

| אפשרות | יתרונות | חסרונות | החלטה |
|--------|---------|---------|-------|
| **audio-separator** (nomadkaraoke, MIT) | בוגרת, 1300+ כוכבים, `pip install`, הורדת מודלים אוטומטית, פעילה | קטלוג המודלים לפעמים מפגר אחרי החדשים ביותר | ✅ **מנוע ברירת מחדל** |
| **pymss** (MIT) | תומכת ב-12 ארכיטקטורות; טוענת קונפיגים ישירות מ-HuggingFace | צעירה, פחות מוכחת | ✅ **מנוע שני**, לגישה למודלים החדשים |
| **MSST** (ZFTurbo, MIT) | קוד המקור של רוב המודלים; הכי עדכני | ספריית אימון, לא ספריית inference נוחה | 🔧 מקור לקונפיגים ולמודלים |
| **MSST-WebUI** | ממשק נוח, קטלוג מודלים ענק | רישיון **AGPL-3.0** — מדביק | ❌ לא נשתמש בקוד |
| **UVR5 (GUI)** | הכי מוכר בקהילה | לא עודכן מאז מרץ 2025 | ❌ לא רלוונטי כספריה |

**החלטה:** שכבת הפשטה `SeparationBackend` עם שני מימושים. מודל חדש נוסף בלי לגעת בשאר התוכנה.

### 2.5 שרשרת ההפרדה המומלצת

```
שיר מקורי (WAV 44.1kHz stereo)
   │
   ├─[1] הפרדה ראשית: ווקאל ↔ פלייבק          ← תמיד
   ├─[2] הפרדת ליווי קולי: ליד ↔ ווקאלים מלווים  ← אוטומטי אם מזוהים
   ├─[3] DeReverb + DeEcho על הליד             ← אוטומטי אם מזוהה הדהוד חזק
   │        └─ תוצר לוואי: "שכבת ההדהוד" נשמרת בנפרד (שימושה נבחן — ראה פרק 6)
   └─[4] Denoise עדין                          ← רק במצב "איכות מרבית"
```

### 2.6 האם Ensemble שווה את זה?

**כנראה כן, אבל רק במצב "איכות מרבית" — וזה ייבדק ולא יונח.** ההערכה מהספרות: שילוב
2–3 מודלים נותן 0.2–0.4dB ומפחית artifacts ייחודיים למודל בודד, בעלות של פי 2–3 זמן.
**זה נכנס לבנצ'מרק של Phase 2 ולא נקבע כברירת מחדל מראש.**

### 2.7 רמות איכות (זמנים = הערכה בלבד)

| רמה | מה קורה | זמן משוער לשיר של 4 דקות |
|-----|---------|--------------------------|
| **מהיר** | מודל יחיד, overlap נמוך | ~1–2 דקות |
| **מאוזן** (ברירת מחדל) | מודל מוביל יחיד + DeReverb לפי צורך | ~3–5 דקות |
| **איכות מרבית** | Ensemble + כל שלבי הניקוי | ~10–18 דקות |

> ⚠️ **הזמנים האלה הם הערכה תיאורטית ולא נמדדו.** הם ייקבעו בפועל ב-Phase 1 (Spike) ו-Phase 2.

### 3.2 ההחלטה: RVC v2 כמנוע ה-MVP — אבל לא כארכיטקטורה

**למה RVC:**

1. **איכות דמיון גוון.** מודל שאומן על 15–30 דקות מהקול היעד נותן דמיון גבוה בהרבה
   ממודל zero-shot שמקבל 10 שניות. בשירה הפער הזה גדול.
2. **יציבות ותחזוקה.** MIT, פעיל, קהילה עצומה.
3. **שליטה.** נותן בדיוק את הידיות שצריך לבעיית המנעד.
4. **מהירות.** ההמרה עצמה מהירה מאוד על ה-GPU שלך.

**⚠️ אבל: לא נועלים את הארכיטקטורה ל-RVC v2.**

כל שימוש ב-RVC יעבור דרך מתאם מפורש בשם `ConversionBackend` (מפורט ב-[architecture.md](architecture.md)).
הסיבה **אינה** שמחכים ל-RVCv3 — **בדקתי, RVCv3 לא שוחרר.** הוא מובטח ב-README של הפרויקט
מאז 2023 והטאג האחרון הוא עדיין `2.3.260718` (v2). הסיבה האמיתית פשוטה יותר:
**התחום זז מהר, ואסור שהחלפת מנוע ההמרה תדרוש שכתוב של התוכנה.**

**Zero-shot:** לא ב-MVP. נשאר כמנוע שני אפשרי מאחורי אותו מתאם, ונבחן בבנצ'מרק של Phase 10.

### 3.3 מודל בסיס (Pretrained) לאימון

**TITAN** (`blaise-tk/TITAN`) — **רישיון מאומת: Apache-2.0** ✅ — מודל בסיס איכותי ל-RVC,
שמאפשר תוצאה טובה בפחות epochs ועם פחות דאטה מהבסיס הרשמי.

### 3.4 Vocoder

ברירת מחדל: **HiFi-GAN-NSF** (הסטנדרטי ב-RVC, יציב ותואם לכל המודלים בעולם).
**RefineGAN** ייבדק בבנצ'מרק — הוא נותן איכות גבוהה יותר אבל מייצר מודלים שתואמים רק חלקית לכלים אחרים.

### 3.5 הפרמטרים של RVC וכיצד נגדיר אותם אוטומטית

| פרמטר | מה הוא עושה (עברית פשוטה) | ברירת מחדל **התחלתית** |
|-------|---------------------------|------------------------|
| `f0_method` | איך מזהים את גובה הצליל | `rmvpe` |
| `f0_up_key` | בכמה חצאי טונים להזיז את הקול | מחושב ע"י מנוע המנעד (פרק 4) |
| `index_rate` | כמה להיצמד לגוון של חומר האימון | 0.6 — 0.75 |
| `protect` | הגנה על עיצורים ונשימות מפני עיוות | 0.33 |
| `rms_mix_rate` | כמה לשמר את הדינמיקה של הביצוע המקורי | 0.25 |
| `filter_radius` | החלקה של עקומת הגובה | 3 |
| `formant_shift` | תיקון "גודל" הקול כשיש הזזת גובה גדולה | מחושב אוטומטית |

> ⚠️ הערכים האלה הם **נקודת פתיחה מהקהילה, לא המלצה מכוילת.** הם נקבעים סופית בבנצ'מרק של Phase 5–6.

## 4. ⭐ הלב של הפרויקט: הפתרון לפער המנעד

### 4.1 מה הבעיה בדיוק

אישה שרה שיר בטווח של, נניח, לה3 עד רה5. גבר ממוצע שר בנוחות הרבה מתחת לזה.
אם פשוט נחליף גוון בלי לגעת בגובה — נקבל גבר ששר בגובה של אישה: קול חנוק,
פאלצטו מלאכותי, ותחושה שמישהו "מתח" קול לגבהים שלא מתאימים לו.

### 4.2 התובנה המרכזית — ובדיוק מה היא כן אומרת ומה לא

יש הבדל אמיתי בין שני סוגי הזזה:

**(א) הזזה של אוקטבה שלמה (12, 24 חצאי טונים).**
תו והתו שאוקטבה מתחתיו הם *אותו תו* מבחינה הרמונית. אם נוריד את השירה בדיוק ב-12
והפלייבק יישאר כמו שהוא — **הכול עדיין בסולם**. זה בדיוק מה שקורה כשגבר שר שיר של אישה בקריוקי.

**(ב) הזזה שאינה כפולה של 12 — משנה את הסולם של השיר.**
אם נוריד את השירה ב-3, חייבים להוריד גם את הפלייבק ב-3, אחרת השירה תישמע צורמת.

> ### ⚠️ תיקון חשוב לניסוח קודם
>
> בגרסה הראשונה כתבתי שהזזת אוקטבה היא **"חינם"**. זה ניסוח מטעה.
> הניסוח המדויק:
>
> **הזזת אוקטבה היא חינם מבחינת הצורך להזיז את הפלייבק — היא אינה בהכרח חינם מבחינת איכות הקול.**
>
> **ומאיפה בכל זאת מגיעה הפגיעה?** לא ממתיחה של הצליל — ב-RVC אין מתיחה, המודל
> **מסנתז מחדש** בגובה החדש. הפגיעה מגיעה משלושה מקורות אחרים:
>
> 1. **חריגה מטווח האימון** — המודל עלול לא להכיר את אזור הגובה שביקשנו ממנו.
> 2. **שאריות דובר במאפייני התוכן** — הייצוג שנשלף מהקול המקורי נושא איתו מעט מידע
>    על הפורמנטים של הזמרת, וזה מתנגש בגוון היעד.
> 3. **מיפוי פורמנטים** — יחסי הפורמנטים צריכים מיפוי מחדש, וזה מתקשה בהזזות גדולות.

### 4.3 האלגוריתם

```
כל הזזה s (בחצאי טונים) מתפרקת ל:   s = 12·k + r
                                      ↑        ↑
                        אוקטבות (לא נוגעות     שינוי סולם (עולה
                          בפלייבק)             באיכות הנגינה)
```

**שלב 1 — פרופיל הקול המקורי בשיר.**
RMVPE על הווקאל המופרד → עקומת F0 → סטטיסטיקה ביחידות MIDI:
`p05, p25, p50, p75, p95`, `min`, `max`. משוקללת לפי אנרגיה ומשך.

**שלב 2 — פרופיל קול היעד.**
כל מודל קול שומר פרופיל שנמדד מחומר האימון שלו:
`comfort_low = p05`, `comfort_high = p95`, `abs_low`, `abs_high`.

**שלב 3 — 🆕 עקומת איכות מול הזזה (חדש בסבב הזה).**
הבעיה בגרסה הקודמת: קנס הפורמנטים (`w5`) היה מספר שהמצאתי.

**הפתרון:** בעת ייבוא או אימון של קול, המערכת מריצה **מדידה חד-פעמית** — המרת בדיקה
קצרה בהזזות `0, −5, −12, −17, +5, +12`, ומודדת בכל אחת דמיון דובר וספירת artifacts.
התוצאה נשמרת בפרופיל הקול כעקומה. **פונקציית העלות עובדת מול עקומה שנמדדה על הקול הזה,
לא מול ניחוש.**

**שלב 4 — פונקציית העלות.**

```
cost(s) =  w₁ · מסת_תווים_מחוץ_לטווח_הנוח(s)
         + w₂ · מסת_תווים_מחוץ_לטווח_המוחלט(s)     ← קנס כבד
         + w₃ · |חציון_מוזז(s) − חציון_היעד|
         + w₄ · קנס_פלייבק(|r|)                     ← r = s mod 12, ממופה ל-[-6..+5]
         + w₅ · עקומת_האיכות_הנמדדת(s)              ← 🆕 נמדד, לא מונח
```

**המפתח:** `קנס_פלייבק` תלוי **רק ב-r**. הזזה של 12 או 24 לא מחייבת לגעת בפלייבק.

> ⚠️ המשקלים `w₁…w₅` הם **פרמטרים לכיול**, לא קבועים. הם ייקבעו בבנצ'מרק של Phase 4
> על שלושה פרופילי קול שונים (ראה [testing.md](testing.md)).

**שלב 5 — הצגה בעברית פשוטה.** 2–3 האפשרויות הטובות, למשל:

> ✅ **מומלץ:** להוריד את השירה באוקטבה שלמה (12 חצאי טונים).
> המוזיקה נשארת בדיוק כמו שהיא.
>
> **אפשרות נוספת:** להוריד 14 חצאי טונים — יתאים עוד קצת יותר טוב לקול,
> אבל אז צריך להוריד גם את המוזיקה ב-2.

### 4.4 הזזת הפלייבק — אסטרטגיה שנבחנת, לא חוק

בגרסה הקודמת קבעתי כלל: **"אף פעם לא מזיזים תופים."** ההיגיון הפיזיקלי נכון —
לתופים אין גובה מוגדר, והזזת גובה מטשטשת את החדות שלהם.

**אבל הכלל היה מוחלט מדי,** כי הוא התעלם מהעלות של הצד השני:
פיצול הפלייבק לשכבות **מכניס artifacts של הפרדה** ובעיות התאמה בין השכבות בחיבור מחדש.

**לכן זה הופך לשאלה אמפירית** עם שתי אסטרטגיות:

| אסטרטגיה | איך | היתרון | המחיר |
|-----------|-----|---------|--------|
| **A — הזזה שלמה** | מזיזים את הפלייבק כמו שהוא | אין artifacts של הפרדה | התופים מיטשטשים |
| **B — פיצול** | בס/תופים/שאר; מזיזים הכול חוץ מתופים | התופים נשארים חדים | artifacts של הפרדה + חיבור |

**התחזית שלי (תיבדק):** ל-`|r| ≤ 2` אסטרטגיה A תנצח, כי הטשטוש קטן והיא לא משלמת על הפרדה.
מעבר לזה — B. **לכן הבנצ'מרק חייב להיות מטריצה של אסטרטגיה × גודל הזזה**, ולא בחירה גלובלית אחת
(ראה [testing.md](testing.md)).

## 6. אחרי ההמרה: תיקונים ומיקס

```
קול מומר (יבש)
   ├─ 1. ניקוי artifacts
   ├─ 2. בדיקת מנגינה (מתאם F0) + תיקון עדין
   ├─ 3. התאמת מעטפת עוצמה למקור
   ├─ 4. De-esser עדין
   ├─ 5. התאמת ספקטרום (EQ match) — אופציונלי
   ├─ 6. טיפול במרחב האקוסטי  ← 🆕 אסטרטגיה שנבחנת (למטה)
   └─ 7. נרמול LUFS
   └──► מיקס + פלייבק → לימיטר → ייצוא
```

### 6.1 🆕 החזרת ההדהוד — אסטרטגיה שנבחנת, לא שלב חובה

בגרסה הקודמת קבעתי כשלב חובה: לשמור את שכבת ההדהוד ולהחזיר אותה. **זה היה מוקדם מדי,
ויש לזה בעיה טכנית שלא ציינתי:**

> שכבת ההדהוד שנשמרה היא ההד של **הזמרת המקורית**. זנב ההד נושא את הגוון שלה.
> להדביק אותו לקול גברי חדש = קול יבש גברי עם זנב נשי. ואם הזזנו גובה — הזנב
> נשאר בגובה המקורי ולא תואם לשירה החדשה.

**שלוש אסטרטגיות שייבחנו זו מול זו ב-Phase 6:**

| אסטרטגיה | איך | סיכון |
|-----------|-----|--------|
| **A — החזרה ישירה** | מוסיפים את שכבת ההדהוד המקורית כמו שהיא | אי-התאמת גוון וגובה בזנב |
| **B — שחזור פרמטרי** | מודדים מהמקור אורך הד ויחס רטוב/יבש, ומייצרים הד חדש על הקול המומר | ההד לא זהה לחלוטין למקור |
| **C — שילוב** | הד חדש כבסיס + מעט מהשכבה המקורית עמוק במיקס | מורכב יותר |

**ברירת המחדל תיקבע לפי התוצאה, לא לפי הנחה.**

### 6.2 🆕 כלי המיקס — ffmpeg במקום DSP עצמי

בגרסה הקודמת כתבתי שנממש EQ, קומפרסור ולימיטר בעצמנו ב-numpy כדי להימנע מ-GPL.
**זו הייתה החלטה גרועה:** לימיטר שקוף באמת (true-peak, oversampling, lookahead,
release תלוי-תוכן) הוא הרבה יותר קשה ממה שזה נשמע, וכל באג שם נשמע ישירות בתוצאה.

**הפתרון: אנחנו כבר אורזים ffmpeg.** יש בו את הפילטרים `alimiter`, `acompressor`
ו-`loudnorm` — ברישיון LGPL, מנוסים על מיליארדי קבצים, בלי תלות נוספת ובלי GPL.

**חלוקת העבודה:**

| משימה | הכלי | רישיון |
|-------|------|--------|
| מדידת LUFS | `pyloudnorm` | MIT |
| נרמול LUFS + לימיטר + קומפרסור | פילטרים של ffmpeg | LGPL |
| EQ (פילטרים ביקוודראטיים סטנדרטיים) | `scipy.signal` | BSD |
| דגימה מחדש | `soxr` (איכות VHQ) | LGPL |
| התאמת מאסטרינג אוטומטית | ❌ `matchering` — GPL, לא ב-MVP | — |

**יעד עוצמה:** ‎-14 LUFS ברירת מחדל, עם אפשרות ל-‎-9 LUFS ("חזק").

שמריצה יחד, בהצלחה: הפרדת RoFormer + RMVPE + RVC inference + `python-stretch`.

**נקודת פתיחה לניסוי (לא החלטה):** Python 3.11, PyTorch יציב עם CUDA שתומך ב-Ada Lovelace (sm_89).

**תוכנית ב' אם ה-Spike נכשל:** שתי סביבות Python נפרדות — אחת להפרדה, אחת להמרה —
שמתקשרות דרך קבצים. פחות אלגנטי, אבל עובד תמיד ומסיר את הסיכון לגמרי.

## 14. סיכום ה-Pipeline המומלץ

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. קליטה      ffmpeg → WAV 44.1kHz/stereo/float32               │
│ 2. הפרדה      Roformer (PolarFormer/Mel-Band) → ווקאל + פלייבק  │
│    2b. ליווי  מודל karaoke → ליד + ווקאלים מלווים    [לפי צורך] │
│    2c. הדהוד  DeReverb → ליד יבש + שכבת הדהוד        [לפי צורך] │
│ 3. ניתוח      RMVPE → עקומת F0 → פרופיל מנעד + זיהוי סולם       │
│ 4. החלטה      מנוע המנעד → s = 12k + r  (+ הסבר בעברית)         │
│ 5. הזזה       פלייבק: אסטרטגיה A או B לפי |r|  [נקבע בבנצ'מרק]  │
│ 6. המרה       ConversionBackend → RVC v2                        │
│ 7. תיקון      artifacts → בדיקת מנגינה → מעטפת → de-ess          │
│ 8. מרחב       אסטרטגיית הדהוד A/B/C  [נקבע בבנצ'מרק]            │
│ 9. מיקס       LUFS + לימיטר (ffmpeg) → סכימה                     │
│ 10. ייצוא     WAV 24-bit + MP3 320kbps                           │
└─────────────────────────────────────────────────────────────────┘
```
