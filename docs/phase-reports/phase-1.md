# דוח סיום — Phase 1: Compatibility Spike + שלד

**תאריך:** 16 באוגוסט 2026
**מכונה שעליה נבדק:** Lenovo 83DJ · Intel Core Ultra 7 155H · 15GB RAM · Intel Arc iGPU
**סטטוס:** 🟡 **הושלם חלקית** — שלושה מתוך ארבעה סעיפי ה-DoD עברו. אחד חסום.

---

## 1. מה נבנה

### חלק א' — ה-Spike

מערכת שבודקת, לכל שילוב של גרסת Python ו-PyTorch, האם כל רכיבי הצינור
מותקנים ורצים **יחד**. לכל מועמד נבנית סביבה מבודדת, מותקן כל הצינור בבת אחת
(כדי לחשוף קונפליקטים עכשיו ולא ב-Phase 5), ומורצות בדיקות אמיתיות.

הבדיקות לא מסתפקות בייבוא — הן מפעילות את הרכיב: כפל מטריצות אמיתי ב-torch,
כתיבה וקריאה של WAV, זיהוי גובה על צליל ידוע, מדידת LUFS על אות ידוע,
**הזזת גובה של אוקטבה שלמה ואימות שהאורך נשמר בדיוק**, ובדיקה שכל פילטרי
ה-ffmpeg הנדרשים למיקס קיימים.

### חלק ב' — השלד

- מבנה הפרויקט, ניהול תלויות, לוגים, קונפיגורציה
- **ארבעת המתאמים** שאושרו: `ConversionBackend`, `SeparationBackend`, `PitchShifter`, `F0Extractor`
- `svc doctor` — בדיקת מערכת בעברית, בטקסט וב-JSON
- הודעת שגיאה בעברית לכל קוד שגיאה, כל אחת אומרת מה קרה ומה לעשות
- תקשורת JSON-RPC בין הממשק למנוע, בתהליכים נפרדים
- CI על Windows: lint, טיפוסים, בדיקות, גבולות ארכיטקטורה, ובדיקת רישוי

## 2. מה נבדק, ומה נמצא

### ✅ ממצא 1: יש מטריצת תלויות שעובדת

**Python 3.11 + torch 2.13.0 + כל הצינור — עובד.** כל 11 הבדיקות עברו.
התוצאה נעולה ב-`constraints.txt` (72 חבילות).

### ❌ ממצא 2: Python 3.12 **שבור** — וזו בדיוק הסיבה שה-Spike קיים

ב-Python 3.12 מנהל החבילות בוחר `librosa 1.0.0`, שהסירה את התלות ב-`audioread`.
אבל `audio-separator 0.44.5` עדיין מייבא אותה. התוצאה:

```
ModuleNotFoundError: No module named 'audioread'
```

זו תקלה שהייתה מתגלה רק ב-Phase 2, אחרי שכבר בנינו עליה.
**הפרויקט ננעל ל-Python 3.11** — לא מתוך העדפה, אלא על סמך מדידה.

### ✅ ממצא 3: הזזת הגובה MIT עובדת

`python-stretch 0.3.1` נטענה על Windows, ביצעה הזזה של אוקטבה שלמה,
והחזירה **בדיוק 44,100 דגימות מתוך 44,100** — החוזה על שימור האורך מתקיים.
זה מאשר את ההחלטה להוציא את Rubber Band (GPL) מהליבה.

### ✅ ממצא 4: ffmpeg מכיל את כל מה שצריך

`loudnorm`, `alimiter`, `acompressor`, `aresample` — כולם קיימים.
ההחלטה להשתמש ב-ffmpeg במקום לכתוב DSP בעצמנו מאומתת.

### 📌 ממצא 5: torch 2.13, לא 2.11

במסמך המחקר כתבתי "PyTorch 2.11". בפועל נפתר 2.13.0.
**זו בדיוק הסיבה שלא ננעלו גרסאות מראש.**

### ✅ ממצא 6: אפס תלויות GPL במטריצה הנעולה

בדיקת הרישוי המובנית רצה על סביבת הפיתוח, שכמעט ריקה — זה לא מספיק.
לכן נבדקו כל **66 החבילות שב-`constraints.txt`** ישירות מול PyPI:

| | |
|---|---|
| הפרות GPL / AGPL | **0** |
| LGPL (מותר בקישור דינמי) | 1 — `soxr` (LGPL-2.1-or-later), כצפוי |
| ללא הצהרת רישיון | 1 — `fsspec` |

מדיניות "בלי GPL בליבה" מאומתת בפועל, לא רק בתכנון.

## 3. 🔴 החסם: אין כרטיס NVIDIA במחשב הזה

בדיקה מלאה של המערכת מצאה:

| | מה שתואר בתכנון | מה שיש בפועל |
|---|---|---|
| מעבד | Intel Core Ultra 7 | ✅ Core Ultra 7 155H |
| זיכרון | 32GB | ❌ **15GB** |
| כרטיס מסך | NVIDIA RTX 2000 Ada, 16GB | ❌ **Intel Arc iGPU בלבד** |

אין שום התקן NVIDIA במערכת — לא בהתקנים פעילים, לא במנוטרלים, ואין `nvcuda.dll`.

**המשמעות:** שלושת מועמדי ה-CUDA לא רצו. הם מסומנים במטריצה כ-`skipped`
ולא כ-`pass` — **לא דיווחתי הצלחה על משהו שלא נבדק.**

**מה זה לא אומר:** זה לא מבטל את Phase 1. שאלת קונפליקטי התלויות — שהיא
השאלה המרכזית של ה-Spike — נענתה במלואה, והתשובה תקפה גם ל-GPU
(גרסת CUDA משנה רק מאיזה מאגר יורד torch, לא את שאר הצינור).

## 5. מה צריך ממך

**החלטה אחת:**

| אפשרות | מה קורה |
|---------|----------|
| **א. יש מחשב אחר עם ה-RTX 2000 Ada** | תריץ שם שתי פקודות (למטה), תשלח לי את הפלט, ו-Phase 1 ייסגר במלואו |

| **ג. הכרטיס אמור להיות כאן** | ייתכן שהוא מנותק או שחסר דרייבר — שווה לבדוק במנהל ההתקנים |

```bash
git clone https://github.com/cdtauman/song-voice-converter C:\dev\song-voice-converter
```

```bash
cd C:\dev\song-voice-converter && uv venv --python 3.11 .venv && uv pip install --python .venv\Scripts\python.exe -e ".[dev]" && python spike\run_spike.py
```

`docs/compat-matrix.md` ואת `constraints.txt`.
