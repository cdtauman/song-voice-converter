# דוח סיום — Phase 1: Compatibility Spike + שלד

**תאריך:** 17 באוגוסט 2026
**מכונת הפיתוח:** Lenovo 83DJ · Intel Core Ultra 7 155H · 15GB RAM · Intel Arc Graphics
**סטטוס:** ✅ **הושלם** — כל סעיפי ה-DoD עברו.

---

## 1. מה נבנה

### שכבת החומרה — שלושה מסלולי ביצוע

SongVoice מריצה את העבודה הכבדה על אחד משלושה מסלולים, **כולם יעדי ליבה**:

| מסלול | חומרה | סדר עדיפות |
|--------|--------|-------------|
| **CUDA** | כרטיסי NVIDIA | 1 |
| **XPU** | Intel Arc / Core Ultra עם Arc משולב | 2 |
| **CPU** | כל מחשב | 3 |

הרכיבים: `ComputeBackend` (שלושת המסלולים), `DeviceManager` (זיהוי ובחירה),
`SupportMatrix` (מה אומת לכל רכיב).

### ⭐ כלל ההוכחה

> רכיב נחשב נתמך על מאיץ **רק אחרי שעומס אמיתי רץ עליו והחזיר תוצאה נכונה.**
> התקנה נקייה, ייבוא מוצלח, או `is_available() == True` — לא מוכיחים כלום.
> מה שלא הוכח, רץ על המעבד.

הסיבה פשוטה: "נתמך" שגוי לא מתגלה עכשיו — הוא מתגלה כתקלה מסתורית באמצע עיבוד שיר.

**כל רכיב נבחן בנפרד.** אין הנחה שמסלול אחד חייב לעבוד לכולם — אם ההפרדה
לא רצה על Intel אבל זיהוי הגובה כן, ההפרדה תרוץ על המעבד והשאר על Intel, באותה עבודה.

### ה-Spike

בונה לכל מועמד סביבה מבודדת, מתקין את כל הצינור בבת אחת (כדי לחשוף קונפליקטים
עכשיו ולא ב-Phase 5), ומריץ עומסים אמיתיים — לא ייבוא, לא זיהוי מכשיר.

### השלד

מבנה הפרויקט · ארבעת המתאמים שאושרו · `svc doctor` בעברית · הודעת שגיאה בעברית
לכל קוד · תקשורת JSON-RPC בין הממשק למנוע בתהליכים נפרדים · CI עם lint, טיפוסים,
בדיקות, גבולות ארכיטקטורה ובדיקת רישוי.

## 2. מה נבדק, ומה נמצא

### ✅ ממצא 1: האצת Intel עובדת — ואומתה בעומס אמיתי

`torch 2.13.0+xpu` זיהה והפעיל את הכרטיס:

| | |
|---|---|
| מכשיר | Intel(R) Arc(TM) Graphics |
| זיכרון | 7.8GB |
| יחידות חישוב | 128 |
| דרייבר | 1.15.39183+1 |
| כפל מטריצות | **שגיאה מקסימלית מול המעבד: 0.0** |

לא רק זיהוי — חישוב אמיתי שהמספרים שלו הושוו למעבד ויצאו **זהים בדיוק**.

### ✅ ממצא 2: שלושת רכיבי הצינור רצים על Intel

| רכיב | מה הורץ על ה-GPU | תוצאה |
|------|-------------------|--------|
| **הפרדה** | STFT ← Multi-Head Attention ← iSTFT (סט האופרטורים של RoFormer) | ✅ אורך נשמר, ערכים תקינים |
| **זיהוי גובה** | **המודל האמיתי של `torchfcpe`, מקצה לקצה** | ✅ זיהה 220.1Hz על צליל של 220Hz |
| **המרת קול** | Conv1d ← Transformer ← ConvTranspose (סט האופרטורים של RVC) | ✅ ערכים תקינים |
| הזזת גובה | — | מעבד מעצם טבעו (ספריית C++ בלי מסלול GPU) |

זיהוי הגובה הוא היחיד שהוכח **על המודל האמיתי**. שני האחרים הוכחו ברמת
האופרטורים — אימות מקצה לקצה עם המודלים האמיתיים שייך ל-Phase 2, כשהמודלים יורדו.

### 📌 ממצא 3: מהירות — לא מסקנה, עדיין

בעומסים הזעירים האלה זיהוי הגובה היה **פי 2.2 מהיר יותר** על Intel (5.7 שניות
מול 12.4), אבל ההפרדה וההמרה היו **איטיות יותר** על ה-GPU.

**זה צפוי ולא אומר כלום על הביצועים האמיתיים** — בעומסים של שניות בודדות, זמן
הקומפילציה של הקרנלים והעברת הנתונים בולעים את הרווח. **השוואת המהירות האמיתית
שייכת ל-Phase 2**, עם מודלים אמיתיים ושירים באורך מלא.

### ❌ ממצא 4: Python 3.12 שבור

ב-3.12 מנהל החבילות בוחר `librosa 1.0.0`, שהסירה את `audioread`. אבל
`audio-separator 0.44.5` עדיין מייבא אותה:

```
ModuleNotFoundError: No module named 'audioread'
```

זו תקלה שהייתה מתגלה רק ב-Phase 2. **הפרויקט ננעל ל-Python 3.11 על סמך מדידה.**

### ✅ ממצא 5: הזזת הגובה MIT עובדת

`python-stretch 0.3.1` הזיזה אוקטבה שלמה והחזירה **בדיוק 44,100 דגימות מתוך 44,100** —
חוזה שימור האורך מתקיים. מאשר את ההחלטה להוציא את Rubber Band (GPL) מהליבה.

### ✅ ממצא 6: ffmpeg מכיל את כל מה שצריך

`loudnorm`, `alimiter`, `acompressor`, `aresample` — כולם קיימים.

### 📌 ממצא 7: torch 2.13, לא 2.11

במחקר כתבתי "PyTorch 2.11". בפועל נפתר 2.13.0.
**זו בדיוק הסיבה שלא ננעלו גרסאות מראש.**

### ✅ ממצא 8: אפס תלויות GPL

כל **86 החבילות** שב-`constraints.txt` נבדקו מול PyPI:

| | |
|---|---|
| הפרות GPL / AGPL | **0** |
| LGPL (מותר בקישור דינמי) | 1 — `soxr`, כצפוי |
| ללא הצהרת רישיון | 1 — `llvmlite` |

## 7. תוספת: מדיניות שימוש חוזר + אימות בזמן ריצה

### מדיניות השימוש החוזר

נכנסה לתוקף מ-Phase 2: **לא כותבים מחדש מה שכבר קיים ובוגר.**
לפני כל רכיב מנוע — בודקים את המימוש ב-AI-RVC, Applio ו-RVC-Project,
ובוחרים: שימוש ישיר ← התאמה ← עטיפה ← הכנסת תת-קבוצה ← מימוש עצמי.

הרישיונות אומתו מול GitHub API: **שלושת המקורות הם MIT.**
המדיניות המלאה ב-[reuse-policy.md](../reuse-policy.md), והמרשם ב-[third-party.md](../third-party.md).

מה שנשאר ייחודי ל-SongVoice: מנוע `s = 12k + r`, ניתוח המנעד, `quality_vs_shift`,
בחירת מסלול לכל שלב, הממשק בעברית, ומערכת הבנצ'מרק.

### `svc verify-backends` — אימות על מחשב המשתמש

הבעיה: מטריצת התמיכה נוצרה ע"י ה-Spike, שהוא כלי פיתוח. על מחשב עם חומרה
אחרת המטריצה המשוגרת פשוט לא נכונה.

הפתרון: הפקודה מריצה את **אותם עומסים אמיתיים בדיוק** על החומרה שלפניה,
ומעדכנת את המטריצה. כלל ההוכחה הפך מבדיקה חד-פעמית לפעולה שאפשר לחזור עליה.

```
            cpu     xpu
הפרדה       ✅       ✅
זיהוי גובה  ✅       ✅
המרת קול    ✅       ✅
הזזת גובה   ✅       —
```

העומסים עברו מ-`spike/smoke_test.py` אל `svc_engine/compute/verify.py` —
**מקור אחד**, שגם ה-Spike וגם האפליקציה משתמשים בו. אין יותר שתי גרסאות שיכולות להתפצל.
